Qué es

Modelos para el trabajo + verificación para cursos

Nació del curso Copilot + Agentes para Empresas (INEMA.CLUB PRO, 9 clases). El curso enseña; el kit ofrece lo que la persona copia. Las herramientas son lo que quedó de útil de la producción del propio curso.

📋 Kit de modelos (10 archivos)

Markdown, en portugués, sin código. Canvas de automatización con agentes, prompts del día a día, prompts de datos, instrucciones de agente, anatomía de flujos, regla de las cuatro elecciones, siete revisiones de gobernanza, ficha de indicador, plan de tres fases, los cinco escalones.

🔎 check-v5.py

Verificador por clase para el formato-curso v5: tiempo estimado vs. declarado, jerga centinela, cobertura de figuras, recuentos del portón, ant duplicación recap ↔ tarjetas, emoji y doble signo de exclamación. Solo Python 3, sin dependencias.

🧪 browser-test.cjs

Prueba headless del motor (Playwright): enrutador, tiempo, figuras en el celular, quiz, práctica, progreso, paneles, tema, persistencia y landing. Termina en ERROS: nenhum o señala qué falló.

Cómo funciona

Un proceso a la vez, en este orden

El orden sugerido para un primer proyecto de agente en una empresa. Cada etapa tiene un archivo del kit; los prompts (del día a día y de datos) se incorporan desde el primer día.

10 · cinco peldaños→ 01 · canvas→ 04 · agente→ 05 · flujo→ 06 · integración→ 08 · indicador→ 07 · gobernanza→ 09 · plan de 3 fases
1

Diseñar

Ubicar el trabajo en los cinco peldaños y completar el canvas de nueve campos con nombres reales.

2

Construir

Agente en Copilot Studio (instrucciones + conocimiento), flujo en Power Automate (aprobación, registro, aviso de error), integración por la mejor vía.

3

Medir

Tres indicadores con meta, responsable y fuente automática; Copilot explica la desviación; la alerta avisa al gestor.

4

Publicar con gobernanza

Siete revisiones antes de salir del borrador y un plan de tres fases con criterio de listo.

El kit

Los diez archivos

Copia el bloque, cambia lo que está entre < >. Los casos (técnica de seguridad laboral, analista de compras, gerente de RR. HH., coordinador financiero) son ficticios.

10 · Los cinco escalones

Usuario → aumentado → diseñador de workflows → constructor de agentes → automatizador. El modelo mental Persona → Agente → Sistemas y el filtro de las tres primeras tareas.

01 · Canvas de automatización con agentes

Nueve campos en una página, ejemplo completado (conciliación de pagos) y la distribución agente / flujo / pantalla / indicador.

02 · Prompts del día a día

Búsqueda que cruza fuentes, correo largo → decidido / pendiente / quién no respondió, reunión → decisiones, responsables y plazos, documento y presentación.

03 · Datos que explican

Excel, Analyst y Researcher: «qué cambió y por qué», hipótesis comprobable entre archivos, investigación interna y externa, las tres revisiones de dos minutos.

04 · Instrucciones de agente

Modelo papel · alcance · reglas · tono para Copilot Studio, lista de verificación para la creación en seis pasos y mantenimiento semanal.

05 · Flujos en Power Automate

Aprobación, documento por vencer y caso llamado por el agente: siempre con registro y aviso de error.

06 · Cuatro opciones y checklist de pantalla

Conector → flujo → automatización de pantalla → Computer Use; registro de proveedor de principio a fin; caso con respuestas.

07 · Gobernanza y lista de riesgos

Siete revisiones antes de publicar, dónde es obligatoria la participación de una persona, argumento para la dirección, minic caso del uso compartido excesivo.

08 · Indicadores

Ficha de indicador, solicitud a Copilot para explicar una desviación, panel mínimo en cinco pasos, base de datos por área, preguntas que un gerente debería poder hacer.

09 · Plan de tres fases y hoja de ruta

Prototipo → ejecución → escala con criterio de listo, los cuatro laboratorios, casos por departamento, roadmap de la empresa en nueve fases.

Requisitos previos

Casi nada

El kit es texto: solo necesitas que la empresa habilite Copilot. Las herramientas requieren Python 3 y, para probar el motor, Node con Playwright.

Para el kit

Microsoft 365 Copilot en la cuenta de trabajo. Copilot Studio y Power Automate para los modelos 04 y 05 (si no tienes acceso, los modelos se convierten en la especificación que solicitará el área de TI).

# nada que instalar
git clone https://github.com/inematds/copilot-agentes-kit

Para check-v5.py

Python 3 estándar. Sin paquetes adicionales.

python3 --version  # 3.8 o más

Para browser-test.cjs

Node 18+ y Playwright con Chromium (o un Playwright ya instalado en otro lugar, mediante PLAYWRIGHT_DIR).

npm i -D playwright
npx playwright install chromium
Guía de uso · paso a paso

Del clon al primer proyecto

Los pasos 1 a 4 son para quienes usarán el kit en el trabajo. Los pasos 5 a 7 son para quienes crean cursos INEMA v5.

1

Clona (o descarga el zip) y abre la carpeta kit/

Diez archivos markdown. Lee primero el 10 (cinco minutos) para situar tu trabajo en los cinco escalones.

git clone https://github.com/inematds/copilot-agentes-kit
cd copilot-agentes-kit/kit && ls  # 01 … 10
2

Usa los prompts en el Copilot de la empresa hoy

Abre 02-prompts-copilot-dia-a-dia.md, copia el bloque de la reunión, cambia lo que está entre < > y pégalo en Copilot de Teams. Regla que aplica a todos: tema con nombre propio + período + lo que quieres ver al final.

Use a reunião <nome e data>. Faça, nesta ordem:
1. Resumo em até 10 linhas.  2. Decisões, sem "talvez".
3. Para cada decisão: responsável (um nome), tarefa e prazo.
4. Pendências sem responsável.  5. Mensagem de acompanhamento cobrando com prazo.
3

Completa el canvas de un proceso real

01-canvas-automacao-com-agentes.md: nueve campos, doce minutos, nombres reales. Marca con ✱ las decisiones que pasan por la lista de riesgos (archivo 07). «Aún no lo sé» sirve en el campo Integración; el archivo 06 lo resuelve después.

CANVAS — <nome do processo>
Objetivo · Entradas · Conhecimento · Decisões (✱ humanas) · Ações
Integração · Validação · Indicadores
4

Construye, mide y publica con gobernanza

Agente en borrador con la plantilla del archivo 04 (prueba con tres preguntas, una fuera del alcance). Flujo de aprobación con el archivo 05 (registro + aviso de error). Tres indicadores con el archivo 08. Antes de publicar, las siete verificaciones del archivo 07. Presenta con el plan de tres fases del archivo 09.

# orden sugerido
10 → 01 → 04 → 05 → 06 → 08 → 07 → 09
5

Verificar un curso v5, clase por clase

Escribe cada lección en un archivo (parts/NN-aula.html) y ejecuta el verificador al cerrar cada una. Imprime el tiempo estimado, el término centinela con contexto, los conteos de la puerta y la verificación antirrepetición recap ↔ tarjetas. Solo después concatena.

python3 tools/check-v5.py parts/01-aula.html
#   palabras=1880 quiz=1 práctica~10min → estimado 20min | data-tempo=20
#   steps=5 figs=5 … manifesto=1 AUSENTE=0
#   DUPLICACIÓN ≥6: …   ← si aparece, reescribe la tarjeta
cat parts/*.html > curso.html
6

Demostrar que el motor está activo

Abre curso.html e landing.html en un Chromium sin ventana, cierra el onboarding, navega, haz clic en el quiz y en la práctica, abre los paneles, cambia el tema, recarga y prueba en el celular. Toma screenshots en la carpeta indicada.

node tools/browser-test.cjs /caminho/do/curso shots
# … statcards: 0/9 clases completadas ~203min restantes
# … mobile body scrollWidth ok: true
# ERRORES: ninguno
# ¿Playwright en otro lugar? PLAYWRIGHT_DIR=/x/node_modules/playwright node tools/browser-test.cjs …
7

Publicar el curso

Portada con la skill capa-inema, index.html con redirect a la landing, .nojekyll, push y GitHub Pages. Catálogo con la skill atualiza-portal.

node ~/.claude/skills/capa-inema/assets/gerar-capa.cjs --repo . --title "Título" --cat "Categoria"
git push && gh api -X POST repos/inematds/<repo>/pages -f 'source[branch]=main' -f 'source[path]=/'
